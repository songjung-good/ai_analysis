# market_docs 검색 평가

설계서 B-3의 검증 방법으로 `market_docs` 검색 성능을 측정했습니다. 작성일 2026-09-30.

## 방법

- 평가 세트: 청크 중 200자 이상에서 한국어 20개, 영어 10개를 무작위 추출(seed 42)하고, LLM이 청크마다 50자 이내 한국어 질문을 생성했습니다. 정답 청크 본문은 `answer_text`로 함께 저장합니다. `data/market/eval/questions.json`
- 그룹: ① 한국어 질문 → 한국어 청크(ko), ② 한국어 질문 → 영어 청크(en), ③ 전체(all)
- 지표: Recall@5, MRR@5
  - **content (주 지표)**: 검색된 청크가 정답 청크 문장의 절반 이상을 담으면 정답. 청크 분할을 바꿔도 비교할 수 있고, 같은 페이지의 다른 청크는 정답으로 치지 않습니다.
  - page (보조): 정답 청크와 같은 페이지면 정답. content보다 관대합니다.
  - 청크 id는 (문서, 페이지, 순번)이라 분할을 바꾸면 다른 본문을 가리키므로 지표로 쓰지 않습니다. 이전 분할에서 content 지표는 청크 id 기준 결과와 같은 값을 냈습니다.
- 모델마다 메모리 내 Chroma에 같은 청크를 적재하고, 운영 코드의 `mmr_search`, `hybrid_search`를 그대로 호출했습니다.

```bash
PYTHONPATH=src python -m ai_investment.retrieval_eval questions market      # 평가 세트 생성
PYTHONPATH=src python -m ai_investment.retrieval_eval score market --models kure bge-m3 e5
PYTHONPATH=src python -m ai_investment.retrieval_eval qualitative market    # 도메인 질문 자동 채점
```

## 현재 결과

운영 설정: KURE-v1, BM25 + Dense similarity(0.4/0.6), 섹션 경계 분할, 청크 1000/150.

| Retriever | ko R@5 | en R@5 | all R@5 | all MRR | page all R@5 |
|---|---:|---:|---:|---:|---:|
| BM25 | 0.650 | 0.200 | 0.500 | 0.344 | 0.567 |
| KURE-v1 dense | 0.900 | 0.800 | 0.867 | 0.676 | 0.900 |
| KURE-v1 MMR | 0.600 | 0.700 | 0.633 | 0.569 | 0.867 |
| **KURE-v1 hybrid (운영)** | **0.900** | **0.800** | **0.867** | **0.671** | **0.900** |
| bge-m3 dense | 0.850 | 0.800 | 0.833 | 0.649 | 0.833 |
| bge-m3 MMR | 0.700 | 0.600 | 0.667 | 0.594 | 0.767 |
| bge-m3 hybrid | 0.850 | 0.800 | 0.833 | 0.612 | 0.833 |
| e5-large dense | 0.900 | 0.400 | 0.733 | 0.537 | 0.733 |
| e5-large MMR | 0.650 | 0.500 | 0.600 | 0.494 | 0.733 |
| e5-large hybrid | 0.900 | 0.400 | 0.733 | 0.572 | 0.733 |

(ko·en·all R@5와 MRR은 content 지표)

## 변경 이력

| 변경 | 운영 hybrid content all R@5 | 근거 |
|---|---:|---|
| 초기: BM25 + Dense MMR(`lambda_mult=0.5`) | 0.633 | |
| Dense를 similarity로 | 0.833 | MMR이 정답 청크 대신 같은 페이지의 다른 청크를 올려, page 지표로는 차이가 없지만(0.867) content 지표로는 크게 떨어집니다 |
| 섹션 경계 분할(`ingest.SEPARATORS`) | 0.867 | 페이지가 청크 크기를 넘을 때 `##`~`####` 제목에서 먼저 자릅니다. 스타트업맵 p.7에서 "(4) AI·SW 플랫폼"과 "맺으며"가 한 청크에 섞이던 문제 해결 |

BM25 가중치 0.4와 0.2는 결과가 같았습니다.

## 도메인 질문

정답 페이지를 PDF에서 직접 확인해 `retrieval_eval.DOMAIN_QUESTIONS`에 넣고, 운영 검색 상위 5개 안의 순위를 코드로 채점합니다.

| 질문 | 정답 | 순위 |
|---|---|---:|
| 휴머노이드 시장 성장률은? | SPRi p.17 (MarketsandMarkets·골드만삭스 전망) | 1 |
| 2024년 전 세계 산업용 로봇 설치 대수는? | IFR p.8 | 1 |
| 한국의 제조업 로봇 밀도는? | 스타트업맵 p.7 (1,012대) | 1 (섹션 분할 전 3) |
| 국내 물류 자율주행 로봇 스타트업은? | 스타트업맵 p.8 물류·유통 자율주행 줄 | 2 |
| 서비스 로봇 중 가장 많이 설치된 용도는? | IFR p.29 (운송·물류 52%) | 3 |

이전 버전의 이 표는 사람이 발췌 앞부분만 보고 채점해, 순위 안에 있던 휴머노이드(p.17)와 로봇 밀도(p.7) 문항을 놓친 것으로 잘못 적었습니다. 그래서 채점을 코드로 바꿨습니다.

## 임베딩 모델

설계서 판정 기준(① ko 그룹 Recall@5, dense)에서 순위가 분할 방식에 따라 바뀝니다.

| 분할 | KURE-v1 | bge-m3 | e5-large |
|---|---:|---:|---:|
| 이전(기본 분할) | 0.850 | **0.900** | 0.850 |
| 현재(섹션 경계 분할) | **0.900** | 0.850 | **0.900** |

차이가 20문항 중 1문항이고 조건에 따라 뒤집히므로 어느 모델도 뚜렷하게 낫지 않습니다. 교체할 근거가 없어 설계서의 KURE-v1을 유지합니다. e5-large는 영어 청크(en)에서 0.4로 크게 떨어집니다.

## 한계

- 문항 수가 30개라 0.05(1문항) 차이는 순위를 확정할 근거가 되지 않습니다.
- 질문을 LLM이 청크를 보고 만들었기 때문에 실제 사용자 질문보다 청크 표현과 가까울 수 있습니다.
- BM25는 한국어 질문 → 영어 문서에서 거의 작동하지 않습니다(R@5 0.2). 공백 기준 토큰화라 언어가 다르면 겹치는 토큰이 없습니다.

tech_docs도 `retrieval_eval questions tech` / `score tech`로 같은 평가를 돌릴 수 있습니다. 섹션 경계 분할은 `ingest.py` 공용 설정이라 tech_docs 적재에도 적용됩니다.
