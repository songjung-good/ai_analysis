## 실행 중 수정한 오류

Tavily 패키지가 네트워크 예외를 `{"error": exception}`으로 반환하는데 기존 wrapper가 이를 빈 목록으로 처리했다. `tools/web.py`에서 오류 응답을 예외로 전파하도록 수정하고 회귀 테스트를 추가했다.

- 수정 전 실행은 네트워크 실패를 `unknown` 정상 결과로 잘못 처리했다. `outputs/agility_business_20260930T042358929241Z.json`은 유효한 검색 성공 결과로 사용하지 않는다.
- 수정 후 샌드박스에서 `ConnectionError`를 확인했으며 `outputs/agility_business_20260930T042423591382Z.json`에 실패 상태를 기록했다.
- 네트워크 접근을 허용한 실행에서 검색과 분석이 완료됐다.
- 전체 테스트 43개 통과. 키·토큰이나 원시 provider 오류는 저장·출력하지 않았다.

## 다음 개선 작업

### 프롬프트 수정 반영

2026-09-30 `business_analysis.py`의 `SYSTEM_PROMPT`에 아래 규칙을 반영했다.

- 날짜가 확인되는 자료끼리 단계 변화를 비교하며 시점 미확인은 추정하지 않는다.
- 제품 세대·고객·현장·계약 방식별로 사실을 구분한다. 전체 단계의 적용 사례와 시점을 설명한다.
- `pilot` 결정 전 상용 계약·실제 운영·매출 근거를 검토한다. 미래 계획과 현재 운영을 구분한다.
- 관련 비용·효과 수치를 적용 범위와 함께 추출하거나 `evidence_assessment.reason`에 인용 출처와 제외 이유를 남긴다.
- 교차 확인은 동일한 주장에 대한 독립 원 출처가 최소 두 개일 때만 사용한다.
- 상세 설명과 요약을 한국어로 작성하며 최종 자체 점검을 요구한다.

출력 모델·State 구조는 유지했다. 전체 테스트 43개 통과. 기존 실행 결과는 보존했으며 수정된 프롬프트로 실제 API를 재호출하지 않았다. 아래 항목의 실제 개선 여부는 동일한 저장 검색 자료를 재사용한 후속 분석에서 확인해야 한다.

1. 자료 시점과 제품 세대를 구분하고 상용화 단계 상충 근거를 명시적으로 비교한다.
2. 가격·효과 수치의 추출 또는 제외 이유를 요구한다.
3. 교차 확인의 독립 출처와 주장별 근거 충분성을 검증한다.
4. 한국어 출력과 발췌 범위 밖 상세 주장 금지를 강화한다.
5. 개선 후 같은 사례를 다시 실행해 품질을 비교한다. 실제 투자 보고서에 사용하기 전 검토가 필요하다.
