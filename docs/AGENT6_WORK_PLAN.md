# 6번 Agent: 투자 판단 구현 및 작업 기록

## 범위와 구현 순서

이 Agent는 현재 기업의 기술·사업성·시장 분석을 종합한다. 외부 검색 Tool 없이 LLM이 항목별 점수와 근거를 구조화하고 Python이 가중합과 최종 상태를 계산한다.

1. 입력과 출력 계약을 확정한다.
2. 점수·근거·중대 위험의 Pydantic 모델과 채점 기준을 작성한다.
3. 현재 기업의 분석에서 인용한 출처만 LLM 입력에 포함한다.
4. 출처 ID와 점수 범위를 검증하고 Python으로 결정한다.
5. 현재 평가 1개만 `evaluations`에 추가할 변경분으로 반환한다.
6. 대체 LLM·Graph 테스트로 경계값, 보류, 실패, 반복 종료를 확인한다.

## 입력 및 누락 처리

- 입력: `selected_startup`, `profile`, `technical_analysis`, `business_analysis`, `market_analysis`, `references`.
- 기업명이 없거나 공백뿐이면 `ValueError`, 잘못된 타입이면 `TypeError`다.
- 기술·사업성·시장 분석 중 하나라도 없거나 빈 사전이면 LLM 호출 없이 `hold`로 종료한다.
- 출처는 현재 기업 입력 및 분석의 `source_ids`, `stage_source_ids`에서 수집한다. 누적 출처 전체나 이전 평가·점수는 LLM에 전달하지 않는다.
- 현재 인용에 대응하는 출처가 없으면 보류한다. 선언한 ID가 `references`에 없으면 입력 검증 오류다.
- 출처 없는 기업명·팀 명단·투자 단계만으로 팀 역량, 매출, 기업가치를 높게 평가하지 않는다.

분석 내부 구조는 현재 Agent별 `dict`를 유지하며 출처 연결 키만 공통 계약으로 요구한다. 기업 기본 정보의 팀·투자 조건을 채점하려면 해당 사실의 근거도 현재 기업 자료에 연결해야 한다.

## 평가 기준

| 항목 | 가중치 | 1점 | 3점 | 5점 |
|---|---:|---|---|---|
| `team` | 30% | 확인된 역량·실행의 중대한 약점 | 관련 전문성과 실행 사례 확인 | 검증된 전문성과 반복적인 사업 실행 성과 |
| `market` | 25% | 확인된 수요·성장 제약 | 고객 수요와 접근 가능한 시장 근거 | 큰 접근 가능 시장과 지속 수요의 강한 근거 |
| `technology` | 15% | 구현·성능의 중대한 한계 확인 | 목적에 맞는 구현 가능성 확인 | 현장 검증된 성능과 기술 차별성 |
| `competition` | 10% | 대체재 대비 확인된 차별성 부족 | 차별점과 경쟁 구도 확인 | 검증 가능한 진입장벽·지속 차별성 |
| `traction` | 10% | 확인된 실적 부진·도입 중단 | 반복 가능한 유료 고객·계약 근거 | 확장되는 매출·계약·현장 도입 근거 |
| `investment_terms` | 10% | 확인된 투자 조건이 불리함 | 단계·가치·거래 조건의 검토 근거 | 위험 대비 유리한 거래 조건 근거 |

2점·4점은 인접 기준 사이의 근거가 있을 때 사용한다. 소수 점수는 1~5 범위 내에서 이유를 설명한다. 자료 부재는 1점이 아니라 `None`이다. 공개 자료로 투자 조건 등이 확인되지 않으면 총점을 만들지 않고 보류한다.

## 결정과 이력

- 가중합 4.0 이상: `invest`.
- 3.0 이상 4.0 미만: `conditional`.
- 3.0 미만: `hold`.
- 항목 누락 또는 핵심 정보 부족: `hold`. 항목 누락 시 총점은 `None`.
- 출처가 있는 중대한 법률·안전 위험: 점수와 무관하게 `hold`.
- 단순한 인증 자료 미공개를 위법 또는 중대한 위험으로 단정하지 않는다.
- 결정은 반올림 전 가중합으로 계산한다.
- 반환 키: `scores`, `investment_score`, `decision`, `decision_reason`, `evaluations`.
- 이력에는 기업명·점수·결정·근거와 항목별 평가·위험·부족 정보·인용 ID를 보존한다. 다른 Agent 소유 키는 수정하지 않는다.

## 검증과 한계

LLM 테스트는 대체 응답이다. 실제 판단 품질이나 근거의 사실성을 증명하지 않는다. 다른 Agent가 미구현 상태라면 전체 실기업 Graph 실행은 완료되지 않는다. 실제 API 호출은 별도 검증 단계에서 수행한다.
