## 1. 담당 역할과 기여 요약

AI 스타트업 투자 평가 시스템에서 **평가할 기업을 찾는 스타트업 탐색 Agent**와 **분석 결과를 투자 보고서 PDF로 정리하는 보고서 생성 Agent**를 개발했다.

- 탐색 단계에서는 웹 검색 결과에서 기업 후보를 추출하고, 투자 단계·비상장 여부·Exit 여부 등 선정 조건을 근거와 함께 검증했다.
- 보고서 단계에서는 공통 State에 누적된 분석·점수·투자 판단·출처를 받아 PDF로 출력했다.
- 각 Agent가 자신에게 허용된 State 키만 반환하도록 기존 개발 계약을 따랐다.
- 출처 검증, 오류 전달, 호출 상한, 후보가 없는 경우의 처리와 테스트를 추가했다.
- Git 브랜치와 커밋을 사용해 작업을 관리하고, 팀 코드 병합 및 PR 준비를 진행했다.

> 현재 상태 주의: 탐색 구현은 `b99ef26` 커밋에서 확인할 수 있지만, 현재 `report` 브랜치의 `agents/discovery.py`는 `NotImplementedError`를 발생시키는 골격이다. 탐색 CLI·전용 테스트·문서도 현재 트리에는 없다. 따라서 아래 탐색 기능은 **구현 이력**이며, 현재 브랜치에서 그대로 실행 가능한 상태라고 발표하면 안 된다. 코드 복구 및 통합 확인이 남아 있다.

## 2. 전체 시스템에서의 위치

```text
스타트업 탐색 [담당]
  → 분야·고객 분류
  → 기술·제품 / 현장 도입·사업성 / 시장·경쟁 분석
  → 투자 판단
  → 보고서 생성 [담당]

후보가 없으면: 탐색 → 보고서 생성
다음 후보 평가가 필요하면: 투자 판단 → 다음 후보 선택 → 분석 반복
```

중간 분석 Agent와 투자 판단은 팀 전체 시스템의 연결 지점이다. 이 문서에서는 해당 기능 전체를 개인 구현 성과로 포함하지 않는다.

## 3. 스타트업 탐색 Agent 구현

근거 커밋: `b99ef26` — `feat: 스타트업 탐색 에이전트 구현`

### 입력과 출력

| 구분 | 내용 |
|---|---|
| 입력 | 관심 분야 `domain`, 선정 조건 `criteria` |
| 조건 | 지역, 허용 투자 단계, 후보 수 상한, 추가 자료 공개 조건 |
| 기본 투자 단계 | Seed, Series A, Series B, Series C |
| 기본 후보 상한 | 5개, 설정 가능 범위 1~10개 |
| 반환 State 키 | `candidates`, `current_idx`, `selected_startup`, `references` |
| 후보 정보 | 기업명, 제품 설명, 투자 단계, 팀 구성원 |

### 처리 과정

1. 입력 조건을 검증하고 미지원 키나 범위 밖의 값을 거부한다.
2. 국문·영문 검색 질의로 초기 후보 자료를 수집한다.
3. LLM의 구조화 응답으로 출처가 연결된 기업명을 추출한다.
4. 기업별로 제품·창업자·최근 투자 라운드와 상장·인수·합병 여부를 추가 검색한다.
5. 분야 적합성, 비상장 상태, Exit 미완료, 제품 및 투자 단계의 근거를 검증한다.
6. 중복 기업을 제거하고 조건을 충족한 후보와 실제 사용한 Evidence를 반환한다.

핵심 선정 조건이 불명확하면 후보에서 제외하도록 구현했다. 팀 정보만 없는 경우에는 이름을 추측하지 않고 빈 목록으로 전달한다. 단순히 인수 기사가 검색되지 않았다는 이유만으로 Exit 미완료를 확정하지 않도록 프롬프트에 판단 기준을 명시했다.

### 신뢰성과 실패 처리

- 기업명 표기를 정규화하고 설명이 붙은 이름을 정리해 중복 후보를 줄였다.
- LLM이 인용한 출처 ID가 실제 검색 결과에 있는지 검사했다.
- 출처 없는 사실·조건 판정과 잘못된 구조화 응답은 한 번 교정을 요청하고, 계속 실패하면 오류를 전달했다.
- 같은 출처에서 다른 발췌문이 검색되면 내용을 보존하도록 병합했다.
- 일시적인 검색 실패는 질의당 최대 2회 시도하고, 장애를 정상적인 ‘후보 없음’으로 바꾸지 않도록 처리했다.

출처 ID 검증은 자료의 존재를 확인하는 장치다. 자료가 주장과 실제로 일치하는지, 정보가 최신인지까지 자동으로 보장하지는 않는다.

### 실행 오류 해결

파일을 직접 실행했을 때 발생한 `ImportError: attempted relative import with no known parent package`를 해결하기 위해 패키지 실행용 CLI와 직접 실행 진입점을 구현했다. 직접 실행 시 공통 CLI로 위임하도록 구성하고, 저장소 밖에서도 `--help`가 실행되는 테스트를 추가했다.

당시 지원한 실행 명령은 다음과 같다. **현재 브랜치에서는 탐색 구현 복구 후 사용해야 한다.**

```bash
PYTHONPATH=src .venv/bin/python -m ai_investment.discover --region 대한민국 --limit 3
.venv/bin/python src/ai_investment/agents/discovery.py --region 대한민국 --limit 3
```

### 탐색이 오래 걸리는 이유와 호출 상한

후보 수와 검색 횟수는 다르다. 초기 검색 후 기업마다 추가 검색과 LLM 검증을 순차 수행하므로 최종 후보가 1개여도 여러 기업을 검토했을 수 있다.

`L = candidate_limit`일 때 재시도를 제외한 상한은 다음과 같다.

- 검증할 기업 수: `min(2 × L, 20)`
- 검색 질의 수: `2 + 2 × min(2 × L, 20)`
- LLM 논리 호출 수: 후보 추출 1회 + 검증한 기업 수

기본값 `L=5`에서는 최대 10개 기업을 검증하고, 검색 22회와 LLM 논리 호출 11회가 발생할 수 있다. 필요한 후보 수가 채워지면 일찍 종료한다. 검색 재시도, 구조화 응답 교정, LLM 클라이언트 재시도는 추가로 발생할 수 있다. `max_iterations`는 Graph의 기업 평가 반복 상한으로, 검색 횟수와는 별도다.

과거 실행에서 언급된 실제 후보명과 소요 시간은 이번에 확인한 기록만으로 확정할 수 없어 수치 성과로 기재하지 않았다.

## 4. 보고서 생성 Agent 구현

근거 커밋: `290707f` — `feat: 보고서 생성 에이전트 구현`

현재 구현: [report.py](../src/ai_investment/agents/report.py)

사용 문서: [REPORT.md](REPORT.md)

### 입력과 처리 과정

1. State의 선정 기업, 기업 프로필, 기술·사업·시장 분석, 점수, 투자 판단, 평가 이력과 Evidence를 읽는다.
2. ChatOpenAI의 구조화 응답으로 짧은 한국어 보고서 문단과 출처 ID를 생성한다.
3. 인용한 출처 ID를 검증하고 실제 인용 자료만 참고문헌에 포함한다.
4. ReportLab으로 PDF를 만들고 PyMuPDF로 페이지 수와 첫·마지막 제목을 검사한다.
5. 검증된 임시 파일을 최종 파일로 이동하고 `{"report": "PDF 절대 경로"}`를 반환한다.

보고서 Agent에는 외부 검색 Tool을 제공하지 않는다. 제공된 분석과 근거만 사용하도록 지시하며, 기업 기본 정보와 최종 점수·판단은 State에서 직접 출력한다. 초안에 인용이 전혀 없는데 Evidence가 제공되어 있으면 한 번 교정을 요청한다.

### 현재 PDF 구성

| 페이지 | 내용 |
|---|---|
| 1 | SUMMARY: 기업, 투자 판단·점수, 판단 이유와 핵심 요약 |
| 2 | 기업 및 사업 개요: 제품, 투자 단계, 창업자·핵심 인력, 사업 내용 |
| 3 | 기술 및 시장 분석 |
| 4 | 투자 평가 및 최종 의견: 점수표, 평가 이력, 평가 근거, 후속 확인 |
| 5 | REFERENCE: 보고서 문단이 인용한 자료 |

- SUMMARY 내용이 반 페이지를 넘으면 오류를 발생시킨다.
- 정상 후보 보고서는 5페이지이며, 후보와 출처가 없는 입력은 LLM 없이 2페이지로 출력한다.
- 한글 폰트를 지원하며 `REPORT_FONT_PATH`로 폰트를 지정할 수 있다.
- 출력 경로는 `output/pdf/`이며, 시간과 중복 방지 접미사로 파일명을 구분한다.
- 빈 요약·최종 의견, 존재하지 않는 출처, 페이지 넘침을 검사한다. 넘친 내용을 자동 축약하는 기능은 없다.
- 생성 PDF와 미리보기는 Git 추적 대상에서 제외했다.

### 요구사항 대비 남은 개선점

| 요구사항 | 현재 상태와 필요한 작업 |
|---|---|
| SUMMARY가 전체 보고서의 핵심 요약 | 분량은 검사하지만 핵심 내용의 완전성은 보장하지 않음. 요약 작성 기준과 검증 보강 필요 |
| 사업 아이디어·시장 규모·팀 역량 | 관련 문단은 있으나 각각의 필수 포함을 강제하지 않음 |
| 시장·기술·규제·경쟁 리스크 및 한계점 | 항목별 구조와 누락 검증 필요 |
| 실제 활용 자료만 REFERENCE에 표시 | 초안에 인용한 출처만 출력. 인용의 의미적 정확성은 별도 검토 필요 |
| 기관 보고서·논문·웹페이지별 서지 형식 | 현재는 제목·URL·페이지·날짜만 출력. 자료 유형, 저자, 발행기관, 학술지 등의 메타데이터와 서식 처리 추가 필요 |
| 여러 기업의 상세 비교 | 현재 선정 기업 중심. 이전 후보는 평가 이력에 남은 이름·점수·판단만 출력 |

현재 구현을 ‘제출용 보고서 규격 전체 충족’으로 표현하지 않는다. PDF 생성 기능과 기본 분량·목차 검증을 구현한 단계다.

## 5. 사용 기술과 선택 이유

| 기술 | 사용 목적 |
|---|---|
| Python, Pydantic | 입력 조건과 LLM 구조화 응답 검증 |
| ChatOpenAI | 후보 추출·검증 및 보고서 초안 생성. 모델명은 `OPENAI_MODEL`로 주입 |
| Tavily | 탐색 Agent의 웹 자료 수집 |
| LangGraph의 State·Node 계약 | 팀의 분석 흐름과 연결, Agent별 쓰기 범위 유지 |
| ReportLab | 한글 투자 보고서 PDF 생성 |
| PyMuPDF | 생성 PDF의 페이지 수·텍스트 검증 |
| unittest, Mock | 외부 API에 의존하지 않는 주요 동작·실패 경로 테스트 |

탐색과 보고서 Agent 자체는 임베딩 모델을 직접 호출하지 않는다. 프로젝트의 기술·시장 RAG 문서에 선정된 임베딩 모델은 `nlpai-lab/KURE-v1`이며, 이는 담당한 두 Agent의 직접 구현 범위와 구분한다.

## 6. 검증 기록

2026-09-30 현재 `report` 브랜치에서 다음 명령을 실행했다.

```bash
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v
```

결과: **총 35개 중 31개 통과, 실제 API를 사용하는 기술 Agent 테스트 4개 건너뜀.** 이 수치는 공통 코드와 기술 Agent 테스트를 포함한 전체 결과이며, 현재 트리에 없는 탐색 전용 테스트는 포함하지 않는다.

보고서 전용 테스트 7개는 모두 통과했다. 주요 검증 내용은 다음과 같다.

- 5페이지 PDF, SUMMARY·REFERENCE, 점수 보존, 인용 자료 포함과 미사용 자료 제외
- 후보가 없을 때 LLM 호출 없이 2페이지 생성
- 잘못된 출처, 빈 초안, 출처가 있으나 인용하지 않은 초안 거부
- 참고문헌이 넘칠 때 오류 처리 및 불완전한 PDF 정리
- 빈 탐색 결과가 실제 보고서 Node로 연결되는 Graph 분기

탐색 구현 커밋에는 조건 필터링, 중복 제거, 호출 상한, 출처 검증, 검색 실패·재시도, 직접 실행, 빈 후보 Graph 분기 테스트가 작성되어 있다. 이번 문서 작성에서는 해당 과거 버전의 테스트를 재실행하지 않았다.

현재 테스트 통과는 전체 서비스의 실제 API 기반 종단 실행 성공을 의미하지 않는다. 탐색 구현 복구와 각 분석 Agent 연결 이후 전체 흐름을 다시 검증해야 한다.

4. 전체 Agent를 연결해 실제 검색부터 최종 PDF까지 실행하고 호출 수·시간·출처를 기록한다.

## 8. 발표 자료에 활용할 구성

| 장표 | 전달할 내용 |
|---|---|
| 1. 담당 역할 | 평가 대상 기업을 찾고 분석 결과를 투자 보고서로 전달하는 시작·마무리 단계 담당 |
| 2. 탐색 흐름 | 초기 검색 → 후보 추출 → 기업별 추가 검색 → 조건 검증 → 후보와 근거 반환 |
| 3. 해결한 문제 | 직접 실행 import 오류, 중복 기업, 출처 없는 응답, 검색 장애, 긴 탐색 시간 |
| 4. 보고서 흐름 | State·Evidence → 구조화 초안 → 출처 검증 → PDF → 결과 경로 반환 |
| 5. 검증과 한계 | 보고서 테스트 결과, 현재 탐색 통합 상태, 필수 항목·참고문헌 개선 과제 |

### 발표용 설명 예시

> 저는 스타트업 탐색 Agent와 투자 보고서 생성 Agent를 개발했습니다. 탐색에서는 웹 검색으로 기업 후보를 찾은 뒤 기업별 추가 검색을 통해 투자 단계와 비상장 여부 등 조건을 검증하고, 근거가 확인된 후보를 반환하도록 구현했습니다. 보고서는 다른 Agent가 축적한 분석과 출처를 받아 최대 5페이지 PDF로 출력하도록 만들었습니다. 개발 과정에서는 직접 실행 오류, 중복 후보, 잘못된 출처와 외부 API 실패 처리를 다뤘습니다. 현재는 탐색 구현을 최신 브랜치에 다시 통합하는 작업과 보고서의 필수 항목·참고문헌 형식을 보완하는 작업이 남아 있습니다.
