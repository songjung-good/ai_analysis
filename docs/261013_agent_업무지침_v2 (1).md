```mermaid
    report --> evaluator
    evaluator -->|pass| END
    evaluator -->|상한 도달| final_report[미통과 사유 반영 PDF]
    final_report --> END
    evaluator -->|rewrite| report
    evaluator -->|research| supervisor
```

- `report` 노드는 **PDF 경로(`report`)와 구조화 초안(`report_draft`)을 같이 State에 저장**한다. 평가는 초안으로 한다. (기존엔 PDF 경로만 남겨서 평가 노드가 내용을 읽을 수 없음. 시간상 렌더링 노드 분리는 안 함)

- 하위 에이전트 → 하위 에이전트 엣지 **없음**. 전부 `supervisor`로 복귀.
- 첫 라운드는 미실행 관점을 **리스트로 반환해 병렬 실행**, 이후엔 부족한 관점만 재실행. 선택된 작업이 모두 합류한 뒤 Supervisor를 실행한다.
- 평가 재조사는 `resume_after_research="investment_decision"`으로 같은 후보의 점수를 갱신한 뒤 보고서로 복귀한다. report_draft가 있는 보완 단계에서는 후보 전환을 막고 마지막 후보 평가 기록을 교체한다. `final_report`는 최종 평가 상태를 반영하는 출력 단계이며 초안/PDF 분리를 새로 구현한다는 뜻은 아니다.
- `stakeholder`, `domain`은 기존 `business` 기능을 `view` 파라미터로 나눠 호출 (에이전트 신규 개발 X).

## 3. Supervisor 규칙

판단은 **코드 규칙**(재현성), 재작업 지시문만 LLM(선택).

```python
VIEWS = ["technical", "market", "stakeholder", "domain"]
MAX_REWORK = 2

def is_sufficient(r: dict) -> bool:
    return r["status"] == "done" and not r["missing_items"] and len(set(r["source_ids"])) >= 2

def supervisor(state) -> dict:
    todo, hints, reasons = [], {}, {}
    for v in VIEWS:
        r = state.get("analyses", {}).get(v)
        n = state["rework_count"].get(v, 0)
        if r is None:
            todo.append(v); reasons[v] = "미실행"
        elif r["status"] == "failed" and n < MAX_REWORK:
            todo.append(v); reasons[v] = f"실패: {state.get('node_errors', {}).get(v)}"
        elif not is_sufficient(r) and n < MAX_REWORK:
            todo.append(v); hints[v] = r["missing_items"]
            reasons[v] = f"근거 부족 missing={r['missing_items']} sources={len(set(r['source_ids']))}"
    # 평가 요청은 구체적인 보완 지시와 함께 한 번만 소비한다.
    verdict = state.get("eval_result") or {}
    for v in verdict.get("target_views", []):
        if v not in todo and state["rework_count"].get(v, 0) < MAX_REWORK:
            todo.append(v); reasons[v] = "평가 노드 재조사 요청"
        if v in todo:
            hints[v] = verdict.get("research_hints", {}).get(v, [])

    if state["step_count"] >= state["max_steps"]:
        todo = []                                   # 종료 가드
    log_decision(state["trace_id"], "supervisor", todo or state["resume_after_research"], reasons)
    return {
        "next_views": todo,
        "rework_hints": hints,
        "rework_count": {v: state["rework_count"].get(v, 0) + (1 if v in todo and state.get("analyses", {}).get(v) else 0) for v in VIEWS},
        "step_count": state["step_count"] + 1,
        "eval_result": {**verdict, "target_views": [], "research_hints": {}} if verdict else None,
    }

def route_from_supervisor(state):
    return state["next_views"] or state["resume_after_research"]
```

**충분성 기준 (README에 그대로 기재)**: status가 done이고 `missing_items`가 비어 있으며 서로 다른 출처 ID 2개 이상. 이는 라우팅을 위한 최소 기준이며 출처의 독립성과 내용 지지는 Hybrid 평가에서 확인한다.

`node_errors[view]`로 해당 관점의 오류를 조회한다. research 요청에는 `research_hints[view]`가 반드시 있어야 하며, 동일 후보를 유지한다. 위 코드는 설계 예시이며 실제 조정 노드 연결은 담당자가 구현한다.

## 4. 하위 에이전트 공통 출력 계약

기존 결과 모델은 유지하고, 반환 직전에 아래 형태로 변환하는 어댑터만 추가한다.

사업성 구현은 기존 BusinessAnalysis에 view_findings·view_missing_items를 추가했다. 관점별 필수 topic과 그래프 호출 예시는 [BUSINESS_VIEWS.md](BUSINESS_VIEWS.md)를 따른다. `view`를 지정한 호출은 analyses·references·node_status·node_errors만 반환하며, 기존 `view` 없는 호출은 business_analysis 출력을 유지한다.

```python
class ViewResult(TypedDict):
    view: str                    # technical | market | stakeholder | domain
    summary: str
    claims: list[dict]           # {"text": str, "source_ids": list[str]}
    missing_items: list[str]     # 충분성 판단 준
    source_ids: list[str]
    status: str                  # done | failed
```

| 관점        | 담당 기능                      | 필수 확인 항목                             |
| ----------- | ------------------------------ | ------------------------------------------ |
| 기술 성숙도 | 기존 technical                 | 핵심 기술, 검증 단계(TRL), 성능 근거, 한계 |
| 시장성      | 기존 market                    | 시장 규모, 수요 근거, 경쟁 구도            |
| 이해관계자  | business(`view="stakeholder"`) | 고객·구매자·공급사, 이해 충돌, 비용 부담   |
| 도메인 적용 | business(`view="domain"`)      | 적용 현장, 도입 사례/PoC, 운영 제약        |

**재작업 입력**: `state["rework_hints"][view]`에 있는 누락 항목을 쿼리 재작성에 반영한다. 반영한 쿼리는 로그에 남긴다.

```python
class GraphState(TypedDict, total=False):

    eval_result: EvalVerdict | None
```

## 6. NODE_WRITES (쓰기 권한 계약)

| 노드 | 쓸 수 있는 키 |
|---|---|
| startup_discovery | candidates, current_idx, selected_startup, references |
| customer_profile | profile, references |
| supervisor | next_views, rework_count, rework_hints, step_count, eval_result (요청 소비) |
| technical / technical_analysis | technical_analysis, analyses, references, node_status, node_errors |
| market / market_analysis | market_analysis, analyses, references, node_status, node_errors |
| stakeholder / domain | analyses, references, node_status, node_errors |
| business_analysis | business_analysis, references (기존 경로) |
| investment_decision | scores, investment_score, decision, decision_reason, evaluations |
| next_candidate | current_idx, selected_startup 및 candidate_reset_update()의 초기화 키 |
| report_generation | report, report_draft |
| evaluator | eval_result, report_attempts, resume_after_research |

`state.py`, `contracts.py`는 **배영환만 수정**. 배은빈은 통합 연결을 담당한다. 다른 사람은 공통 타입·초기화 함수를 import한다.

- 하위 Agent는 자기 관점의 analyses·node_status·node_errors 키만 반환한다. guard가 다른 관점 키 쓰기와 analyses 키·view 불일치를 차단한다.
- 후보 초기화는 병렬 작업 합류 후 단일 next_candidate에서 `candidate_reset_update()`를 호출한다. `analyses={}`만 반환해서는 초기화되지 않는다.
- 초기화는 기존 profile·분석·점수·투자 판단과 새 관점·작업 상태·평가 요청을 함께 지운다. 출처·후보 평가 이력·전역 step_count·trace_id는 유지한다.
- 실제 허용 키는 `contracts.NODE_WRITES`, 상세 사용법은 [STATE_CONTRACT.md](STATE_CONTRACT.md)가 기준이다.

## 7. 품질 평가 노드 (Hybrid)

**입력**: `report_draft`(문단별 `text` + `source_ids`) + `references`(Evidence의 `excerpt`, `url`). PDF가 아니라 구조화 초안을 평가한다.

**선행 조건 (보고서 담당)**: `ReportDraft`에 4관점 섹션(`technical`, `market`, `stakeholder`, `domain`)과 `risks` 섹션을 추가한다. `recommendation`은 `decision_basis`(점수 근거 서술)로 바꾼다. 이게 없으면 커버리지·중립성 규칙이 성립하지 않는다.

**판정 흐름**: 규칙 4종 계산 → Judge 1회 호출(규칙 결과를 함께 제공) → 항목별 최종 판정.

- 규칙이 **확실한 실패**(빈 섹션, 출처 없는 관점)면 Judge 없이 바로 미달.
- 금지어처럼 **오탐 가능한 규칙**은 "경고"로만 Judge에 넘기고 판정은 Judge가 한다.

| 항목          | 규칙 (코드, 결정적)                                                                | LLM Judge (temperature 0, 구조화 출력)                                                        |
| ------------- | ---------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Groundedness  | 4관점·리스크 섹션의 문단 중 `source_ids`가 빈 문단 비율 ≤ 20%                      | 인용 문단 text와 해당 Evidence `excerpt`를 함께 주고, 발췌가 주장을 지지하는지 문단 단위 판정 |
| 중립성        | 금지 표현 목록 매칭 → **경고만** (예: "압도적", "무조건", "확실한 수익", "독보적") | 판정 근거가 점수·출처로 제시됐는지, 과장·홍보성 서술이 있는지                                 |
| 편향 통제     | 관점별 서로 다른 출처 도메인(url host) ≥ 2, `risks` 섹션 문단 ≥ 1                  | 유리한 근거만 골라 쓰지 않았는지, 회사 자체 주장과 외부 근거를 구분했는지                     |
| 관점 커버리지 | 4관점 섹션 각각 문단 ≥ 1 + summary 존재                                            | 각 섹션이 4장의 필수 확인 항목을 실제로 다뤘는지                                              |

**Judge 프롬프트에 반드시 넣을 정의**

- 중립성 = 투자 판정 자체는 허용하되, **코드가 계산한 점수와 출처로 근거를 제시**하고 단정·과장 표현이 없을 것. 이 정의가 없으면 투자 판정 문단 때문에 매번 중립성 미달이 나온다.
- Judge 출력 파싱 실패 → 1회 재호출, 그래도 실패하면 미달.

**루프 카운터**: rewrite든 research든 **미달이면 무조건 `report_attempts` +1**. 재조사할 관점의 상한이 이미 소진되면 미통과로 종료한다. 재조사가 가능하면 같은 후보를 보완하고 보고서로 복귀한다.

```python
class EvalVerdict(TypedDict):
    passed: bool
    items: dict[str, dict]        # {"groundedness": {"passed": bool, "reason": str}, ...}
    action: str                   # pass | rewrite | research
    target_views: list[str]       # research일 때 재조사할 관점
    feedback: list[str]           # rewrite일 때 보고서에 줄 수정 지시
    research_hints: NotRequired[dict[str, list[str]]]  # research일 때 관점별 보완 지시 필수
```

**실패 분기 (2가지만)**

| 실패 원인                            | action   | 다음 노드                        |
| ------------------------------------ | -------- | -------------------------------- |
| 인용 누락·금지어·섹션 구성 문제      | rewrite  | report (feedback 반영)           |
| 관점 근거 자체가 부족·단일 출처 편중 | research | supervisor (target_views 재조사) |

`report_attempts`는 평가 미달 횟수다. 초기값 0, 미달마다 +1. **최초 초안 + 보완 최대 2회**를 허용하므로 1·2번째 미달은 보완하고, `report_attempts > 2`인 3번째 미달에 종료한다. 통과하면 즉시 완료한다.

research일 때 관점별 `research_hints`와 `resume_after_research="investment_decision"`을 반환한다. 재조사 후에도 현재 후보를 유지한다. 재조사 요청은 Supervisor가 한 번만 소비한다. 필요한 관점의 재작업 상한이 이미 소진되면 의미 없는 반복 없이 미통과 종료한다.

종료 전 최종 eval_result의 미통과 사유를 PDF에 반영해 다시 출력한다. 이미 만들어진 PDF가 최종 평가 사유를 자동으로 포함한다고 가정하지 않는다. 미통과 PDF는 성공 제출 사례와 구분한다.

## 8. 트레이스 확보 전략 (동적 실증 20점)

- `.env`에 `LANGCHAIN_TRACING_V2=true`, `LANGCHAIN_PROJECT=agent-supervisor` 설정.
- 실행 시 `config={"metadata": {"trace_id": ...}, "run_name": f"supervisor-{trace_id}"}`.
- **캡처해야 할 장면**: ① 첫 라운드 4관점 병렬 ② 특정 관점만 재작업 ③ evaluator → report 재작성 또는 → supervisor 재조사 ④ 정상 종료.
- 규칙 기반이라 `missing_items`가 나오면 재작업이 자연 발생한다. 실행 2~3회 중 가장 잘 보이는 것을 제출한다. **조작한 Mock 트레이스는 제출하지 않는다.**
- 파일명: `tracing-1.png`, `tracing-2.png` … 순서대로.
